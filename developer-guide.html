Keith & Co. Consulting — Developer Guide

A technical walkthrough of how this site is built, for whoever picks it up next. It explains the patterns and the reasoning behind them — the day-to-day status (what's outstanding, what changed recently) lives in CLAUDE.md instead, since that file gets updated every time the content changes and this one won't.

Plain HTML/CSS/JS, no build step, no framework Last written 2026-08-14 See CLAUDE.md for current TODOs

Overview

Static marketing site for Keith & Co Consulting (Pty) Ltd, a South African event infrastructure and project management company. Five HTML pages, one stylesheet, one script file, no dependencies, no package.json, nothing to compile. That's a deliberate choice, not an oversight — keep it that way unless the client's needs genuinely outgrow it.

Everything renders straight from these files on any static host. Open index.html in a browser and it works; there's no dev server requirement, though running one (see Run & deploy) makes relative paths behave exactly like production.

Design system

Everything lives in CSS custom properties at the top of styles.css. The swatches and type samples below are rendered live from those actual variables and font files — not hand-copied values — so if they ever look wrong, the stylesheet itself changed and this page automatically reflects it.

Colors

Brand rule: navy + greyscale only. No accent hues, no gradients outside the navy/grey family — this is a client CI constraint, not a style preference, so don't introduce new colors without checking with the client first.

CONSULTING
--font-wordmark-sub · Myriad Pro (Adobe Fonts) → Archivo

Used only for the small "CONSULTING" subtext under the logo (header + footer) — nowhere else. Loaded via an Adobe Fonts (Typekit) web-project kit, linked in the <head> of index/about/services/contact.html as <link rel="stylesheet" href="https://use.typekit.net/lxe2zei.css">.

Licensing gotchaThe client is on Adobe's free plan, which only includes Myriad Pro Bold (700) and Bold Condensed — not Semibold (600), which the CSS design originally called for. Rather than ask for 600 and let the browser silently substitute the nearest available weight, .brand .name .sub explicitly sets font-weight:700 — a deliberate match to what's actually licensed, not an accident. Upgrading to Semibold needs a Creative Cloud subscription; if that ever happens, activate Semibold at fonts.adobe.com/fonts/myriad — the same kit URL picks it up automatically, nothing to relink.

Diamond motif

A 45°-rotated square, taken directly from the logo mark. Used as list bullets, eyebrow-label markers, social icons, and decorative background shapes (see .about-visual::before/::after in styles.css for an example of the shape used as an oversized background accent). The CSS class is .dia. When adding new bullet points or list markers anywhere on the site, reach for this before reaching for a generic • or browser default marker.

JavaScript — js/main.js

One file, no bundler, no external libraries by design (see CLAUDE.md — "Vanilla only" is a stated constraint, not an accident). Each feature is a small, independently-guarded block: it checks the relevant element exists before doing anything, so the same file loads on every page without errors even though most blocks only apply to one or two pages.

BlockWhat it does
Footer yearFills #yr with new Date().getFullYear()
Service preselectOn contact.html?service=slug, matches slug against each <option data-slug> in #sv and selects it — this is how the "Enquire about this service" buttons on services.html land on the right dropdown value
Hero sliderindex.html only. setInterval auto-advance every 6s, dot-click jumps + resets the timer, skips auto-start entirely under prefers-reduced-motion
Testimonial pauseSee Testimonials below
Mobile menuToggles .open on #mainnav and the toggle button, syncs aria-expanded, adds .nav-open to <body>; closing on nav-link click keeps it from staying open after navigation
Active navCompares location.pathname's basename against each nav.main a[href] and adds .active — no page needs to hand-mark itself active
Scroll revealIntersectionObserver (threshold 0.12) adds .in to any .reveal element once it's ~12% visible, then unobserves it — one-shot, not re-triggered on scroll-up
Enquiry formSee Contact form below
ConventionNew interactive features should follow this same pattern: a guarded block, a short comment explaining why (not what — the code already says what), and respect for prefers-reduced-motion wherever animation is involved.

Image galleries

Two visually different components, same underlying mechanism:

  • .about-visual .gallery — the "about teaser" gallery on index.html and the "who we are" gallery on about.html
  • .sd-media .sd-gallery — one per service line on services.html

Both are a fixed aspect-ratio:3/2 box containing stacked .g-slide divs, each with an inline background-image:url(...). They crossfade via a galleryFade keyframe (opacity + a subtle scale(1.04)→scale(1) Ken Burns drift) with staggered animation-delay per slide.

<div class="gallery">
  <div class="g-slide" style="background-image:url('assets/images/example-1.jpg')"></div>
  <div class="g-slide" style="background-image:url('assets/images/example-2.jpg')"></div>
  <div class="g-slide" style="background-image:url('assets/images/example-3.jpg')"></div>
</div>

The default timing (no modifier class) is tuned for exactly 4 slides. For any other count, add a modifier class so the crossfade cycles evenly:

Slide countClassCycle duration
2gallery-210s
3gallery-315s
4(none needed)20s
5gallery-525s

Changing slide count without updating this class doesn't break anything visibly obvious — the crossfade just paces unevenly (e.g. a gap where no slide is visible, or two overlapping). Easy to miss in review.

The recurring gotcha (hit twice already — read this before touching a gallery)

Two separate failure modes, same symptom: "the image isn't showing right"

1. Cropping. background-size:cover fills the fixed 3:2 box by cropping whatever doesn't fit. Source photos close to a 1.5 aspect ratio look untouched; a 16:9 photo (1.78) or a repurposed social-card crop (1200×630, 1.9) loses 15–20%+ off each side. This has happened twice: once from reusing an Open Graph card crop as a gallery slide, once from a naturally panoramic photo. Fix, in order of preference:

  1. Check assets/images/_originals/ for a full-resolution master and resize/crop that to ~3:2, instead of reusing an already-cropped derivative.
  2. If no better source exists, override just that slide's inline style with background-size:contain;background-color:var(--navy-deep) — this letterboxes the full image instead of cropping it. Precedent: the electrics and shell-build-2 slides on services.html.

2. Broken references. background-image:url(...) failures are silent — no broken-image icon, nothing in the rendered page, just an empty slide. This happens whenever a replacement photo is saved under a different filename or extension (.jpg → .jpeg is the recurring one) without updating the HTML, or when a slide count changes (an image added or removed) without updating the gallery-N class. Always grep the new filename against the HTML before assuming a swap is done.

Testimonials — contact.html

.t-stage crossfades .t-slide children, tuned specifically for 2 slides (7s/14s stagger) — not the general-purpose gallery-N system above, this one's bespoke. A :only-child rule renders statically (no animation) if there's ever just one testimonial.

<div class="t-stage reveal">
  <div class="t-slide">
    <div class="stars" aria-label="5 out of 5 stars">★★★★★</div>
    <div class="t-text">
      <p>Quote text…</p>
      <!-- more <p> tags here are fine — .t-text handles multi-paragraph quotes -->
    </div>
    <div class="who">
      <img class="t-logo" src="assets/logos/client-x.jpg" alt="Client name">
      <strong>Person — Title, Company</strong>
    </div>
  </div>
  <!-- second .t-slide … -->
</div>

Click/tap to pause: clicking anywhere on .t-stage, or focusing it and pressing Enter/Space, toggles a .paused class that sets animation-play-state:paused on both slides at once — pausing only the clicked slide would desync the alternation. A small "Paused — click to resume" label appears via CSS (::after) while paused. This is wired up in main.js only when there's more than one .t-slide, so it's a no-op with a single testimonial.

Consistent height + "Read more": every quote lives in a .t-text wrapper clamped to max-height:100px, so short and long testimonials present at the same size instead of one dwarfing the other. On page load (after document.fonts.ready, so measurements use final font metrics, not a fallback font), main.js checks each slide's scrollHeight against its clamped clientHeight — only where the real content is taller does it tag .t-text with .has-more (which is what turns on the bottom fade-out) and inject a "Read more" button. Clicking it sets max-height to the text's true scrollHeight for a clean expand, and force-pauses .t-stage so it can't crossfade away mid-read. This re-measures per page load at the current viewport, so the same testimonial can render fully on desktop and get a "Read more" on a narrower mobile width where it wraps to more lines — that's expected, not a bug.

Adding a 3rd testimonialIsn't automatic like the gallery system — .t-stage's timing is hardcoded for 2. You'd need a new nth-child(3) delay rule and a recalculated testiFade duration/percentage split in styles.css.
Box height tracks content, not a magic number.t-stage used to be a fixed min-height:320px with .t-slide absolutely positioned inside it — since absolutely-positioned children don't stretch their parent, this worked only by luck for short quotes and silently overflowed the first time a much longer testimonial (Batseta's full letter) was added. Fixed by making .t-stage a CSS grid with every .t-slide sharing grid-area:1/1 — grid auto-sizes the shared cell to the tallest child, so the box always fits whatever text is actually there. If you ever need go back to independently-positioned slides for some reason, re-add an explicit height budget generous enough for your longest realistic quote, not a number that merely fit whatever existed at the time.
Don't fade what isn't hiddenThe .t-text::after fade-out is scoped to .t-text.has-more, not the base class — an early version applied it unconditionally based on the box being near its clamp height, which falsely implied hidden content on a testimonial that simply filled the box exactly. Also watch z-index here: .t-slide p has z-index:1 (to sit above the decorative ::before quote mark), which will silently paint over the fade overlay unless the fade itself has a higher z-index — it does (2), but if you touch this again and the fade stops showing, that stacking order is the first thing to check.

Only include the .stars row when the source material actually was a star rating. One existing testimonial (Batseta) is a formal signed recommendation letter, not a star review, so it's rendered without stars — adding them would misrepresent something the client never gave.

Contact form

form.enquiry on contact.html posts to Formspree. Current endpoint:

<form class="enquiry reveal" action="https://formspree.io/f/xzepgqwg" method="POST">

This has already been changed twice as the client set up and re-set-up their Formspree form — expect it to happen again. It's a one-line edit: just swap the action URL, nothing else in the form or in main.js needs to change, since the JS reads form.action dynamically rather than hardcoding it.

  • _gotcha — hidden honeypot field, spam trap (leave it alone, don't remove it)
  • _subject — hidden field setting the email subject line Formspree sends
  • #sv — service dropdown, auto-preselected via the ?service= query param (see JavaScript)

main.js intercepts submit and does a fetch() POST with Accept: application/json for an inline success/error message (.form-note, toggling .is-success/.is-error) instead of a page redirect. This is progressive enhancement, not a replacement for the plain form — the action/method attributes still work correctly (via Formspree's own redirect) if JavaScript fails to load.

SEO & meta

Open Graph and Twitter Card tags are in the <head> of all four main pages. sitemap.xml and robots.txt live at the site root and list the same four pages (not coming-soon.html).

Run & deploy

Local

No build step. From inside this folder:

npx serve .
# or
python3 -m http.server 8000

Opening index.html directly (double-click, file://) also works for quick checks, but a real server behaves more like production for relative paths.

Deploy

Any static host works — there's no netlify.toml or equivalent build config in this repo, meaning whichever host is used just needs "no build command, publish directory = repo root." README.md lists Netlify, Vercel, and Cloudflare Pages as known-good options with zero configuration.

Git

Nesting quirkThis keithandco-site/ folder is its own git repository. If it lives inside a parent folder that is not itself a git repo (as it did during this handoff), make sure your terminal/IDE is scoped to this folder before running git commands — running them one level up will silently do nothing or target the wrong repo.
